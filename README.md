# Parameterized CRC-32 Generator/Checker

CRC-32 (Ethernet) in Verilog, in two architectures: a bit-serial version
(1 bit per clock) and a parallel version (8 or 32 bits per clock, set by the
`DW` parameter). All versions are checked against Python's `zlib.crc32`, and
the checker is tested with injected bit errors.

## Features
- Bit-serial CRC-32: one bit per clock, the simple baseline
- Parallel CRC-32: `DW` bits per clock (multiple of 8), tested at 8 and 32
- Standard CRC-32 settings: polynomial `0x04C11DB7` (reflected `0xEDB88320`),
  initial value `0xFFFFFFFF`, LSB-first bits, final inversion
- Checker mode: feeding a message followed by its own CRC (low byte first)
  gives a fixed residue of `0x2144DF1C` when there are no errors
- Self-checking testbenches with a Python golden reference
- Lint-clean under Verilator `-Wall`

## Run it
Requires Icarus Verilog, Verilator, Python 3
(`sudo apt install iverilog verilator`). Optional: GTKWave and Yosys.

    make sim       # serial CRC-32 of "123456789", expects 0xCBF43926
    make simrand   # serial CRC vs zlib on 200 random messages
    make simpar    # parallel CRC (8 and 32 bit) vs zlib on the same messages
    make simerr    # error-injection test of the checker
    make lint      # Verilator lint of both modules
    make clean

The random vectors are generated by `scripts/gen_vectors.py` (fixed seed, so
runs are reproducible) and written to `vectors.hex`.

## How it works
A CRC is a 32-bit register updated once per data bit: shift right by one, and
if the bit shifted out XOR the incoming bit is 1, XOR in the polynomial.
The serial design does exactly one such step per clock.

The parallel design applies `DW` of these steps back to back as combinational
logic in a single clock. A fixed-length loop in a function does this, so it is
correct by construction (it repeats the serial step) and synthesizes into a
network of XOR gates.

## Verification

| Test | What it checks | Result |
|---|---|---|
| `make sim` | CRC-32 of `"123456789"` equals the standard `0xCBF43926` | PASS |
| `make simrand` | Serial CRC vs `zlib.crc32`, 200 random messages (0 to 16 bytes, empty message included) | 200 checked, 0 errors |
| `make simpar` | Parallel DW=8 vs `zlib.crc32`, same 200 messages | 200 checked, 0 errors |
| `make simpar` | Parallel DW=32, messages whose length is a multiple of 4 bytes | 73 checked, 0 errors |
| `make simerr` | Checker on clean messages, injected single-bit errors, injected multi-bit errors | see below |

Error-injection output:

    clean messages : 200 checked, 0 false alarms
    single-bit errs: 18344 injected, 0 missed
    multi-bit errs : 1000 injected, 0 missed
    RESULT: PASS

The injection test appends each message's CRC and checks for the residue.
It flips every single bit, in both the data and the CRC field, and also flips
random sets of 2 to 5 bits. A CRC-32 is guaranteed to detect all single-bit
errors. The multi-bit trials are random, so they show detection in practice
and are not a proof.

## Synthesis (Yosys, generic gate library)

| Version | Bits/clock | Flip-flops | Logic cells | Total cells |
|---|---|---|---|---|
| Serial | 1 | 32 | 79 | 111 |
| Parallel, DW=8 | 8 | 32 | 182 | 214 |
| Parallel, DW=32 | 32 | 32 | 537 | 569 |

Throughput grows 8x and 32x, while area grows about 1.9x and 5.1x. All three
have exactly 32 flip-flops (the CRC register) and no latches. About 65 cells
in each version are fixed overhead (output inversion and initialization).

Reproduce:

    yosys -p "read_verilog rtl/crc32_serial.v; synth -top crc32_serial -flatten; stat"
    yosys -p "read_verilog rtl/crc32_par.v; chparam -set DW 8 crc32_par; synth -top crc32_par -flatten; stat"
    yosys -p "read_verilog rtl/crc32_par.v; chparam -set DW 32 crc32_par; synth -top crc32_par -flatten; stat"

## Limitations
- These are generic gate counts with no timing. The XOR network gets deeper
  as `DW` grows, so the achievable clock frequency drops, and the real speedup
  is below 8x and 32x. Measuring fmax needs a timing-aware flow.
- Only CRC-32 is implemented. The polynomial and initial value are constants
  in the source, not parameters.
- The parallel module takes whole `DW`-bit words only. There is no byte-enable
  logic for a partial last word, so the DW=32 test only covers messages whose
  length is a multiple of 4 bytes.
- Not tested with formal methods.
